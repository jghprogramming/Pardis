# گام بعدی: راه‌اندازی پروژه واقعی

این سند، تصمیم‌هایی را که قبل از ساخت مخزن GitHub و پروژه Supabase
لازم است جمع می‌کند تا آن مرحله با یک تأیید، بدون رفت‌وبرگشت، انجام شود.

## تصمیم‌هایی که فقط شما باید بگیرید

1. **حساب GitHub:** مخزن خصوصی باشد (پیشنهاد می‌شود) یا عمومی؟
2. **حساب Supabase:** پروژه با چه نامی و در چه منطقه‌ای ساخته شود؟
   منطقه نزدیک به کاربران ایران، تأخیر کمتری می‌دهد؛ انتخاب نهایی با شماست.
3. **مرچنت زرین‌پال:** فعلاً فقط محیط آزمایشی (Sandbox) وصل شود، یا
   مرچنت واقعی هم از همین حالا آماده باشد؟ اتصال واقعی، مرحله جداگانه
   بعد از تست است.
4. **دامنه:** فعلاً لازم نیست؛ دامنه اختصاصی را موقع انتشار نسخه اصلی
   انتخاب می‌کنیم.

## ترتیبی که بعد از تأیید شما انجام می‌شود

1. `git init` در همین پوشه، Commit اولیه، ساخت مخزن GitHub و اتصال به Vercel.
2. ساخت پروژه Supabase و اجرای `supabase/migrations/001_init.sql` و
   سپس `supabase/migrations/002_rls.sql`.
3. **قبل از هر استفاده واقعی: بررسی و اعمال سیاست‌های Row Level Security.**
   پیش‌نویس RLS در `002_rls.sql` نوشته شده، ولی هنوز روی هیچ پایگاه داده
   واقعی اجرا و تست نشده است. همچنین توجه کنید که در `001` ستون اتصال
   ساکن به حساب کاربری‌اش وجود نداشت و `002` آن را با
   `units.resident_id` اضافه می‌کند؛ و اولین حساب مدیر محصول نباید از
   طریق ثبت‌نام در اپ ساخته شود، بلکه باید از ویرایشگر SQL سوپابیس
   (که RLS را دور می‌زند) نقش `product_owner` بگیرد، وگرنه هر کاربری
   می‌توانست خودش را مدیر محصول کند.
4. پیاده‌سازی ورود و نقش‌ها (مدیر محصول، مدیر ساختمان، ساکن)، سپس ماژول
   پلن و اشتراک.
5. پیاده‌سازی واحد، دوره شارژ و صورت‌حساب با منطق `src/lib/charges.ts`.
6. اتصال آزمایشی زرین‌پال، سپس اتصال واقعی و انتشار نسخه اصلی.

## چیزهایی که در این مرحله آماده شد (وضعیت ۴ آبان ۱۴۰۵)

- `src/lib/charges.ts`: محاسبه هر چهار روش شارژ، جریمه دیرکرد، مانده و
  وضعیت صورت‌حساب، و تقسیم مساوی هزینه خاص دوره بین واحدها بدون خطای
  گرد کردن. «ترکیبی» یعنی مبلغ ثابت + متراژ + نفر.
- `src/lib/jalali.ts`: نمایش تاریخ شمسی با Intl و اعداد فارسی.
- `src/lib/supabase.ts`: اتصال مرورگر به Supabase از روی متغیرهای محیطی.
- `src/app/layout.tsx`: فونت وزیرمتن حالا با `next/font/google` بارگذاری
  می‌شود (وزن‌های ۴۰۰، ۵۰۰ و ۷۰۰) و روی `body` اعمال شده است؛ توجه کنید
  که این کد هنوز با `next build` تست نشده، چون وابستگی‌های پروژه نصب
  نشده‌اند.
- `supabase/migrations/002_rls.sql`: پیش‌نویس سیاست‌های Row Level Security
  برای هر سه نقش، به‌همراه ستون `units.resident_id` که در `001` جا افتاده
  بود. این فایل هنوز روی پایگاه داده واقعی اجرا نشده است.
  تصمیم‌های تأییدشده در ۴ آبان ۱۴۰۵ (از پیام کاربر): ساکن هزینه‌های
  ساختمان خودش را هم می‌بیند (فقط خواندن)، مدیر ساختمان رکوردهای ساختمان
  خودش را حذف هم می‌تواند بکند، و اولین حساب مدیر محصول از ویرایشگر SQL
  سوپابیس ساخته می‌شود.

## چیزهایی که هنوز آماده نیست — صریح، نه در قالب ادعا
- پوشه‌های `components/`، `features/*` و `app/api/zarinpal/` خالی‌اند و
  کدی ندارند.
- ورود واقعی کاربران و اتصال واقعی زرین‌پال پیاده نشده است؛ RLS فقط در
  حد پیش‌نویس فایل است و هنوز اعمال و تست نشده است.
- هنوز هیچ مخزن Gitای در این پوشه ساخته نشده است.
